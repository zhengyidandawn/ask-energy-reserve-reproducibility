# 编写记录（REQ-1）

我是运行分析岗 REQ-1。本班按 `独立请求编写说明.md` 和 `决策时信息表.md` 写了 48 条向上备用研究请求，没有去翻冻结包里的原文。

## 从哪类值班场景想的

我按自己平时往研究入口丢话的习惯写，场景大致是这些：

- 早高峰前把 GD 一小时那档先排上，只要安排，不要在群里报数。
- ERCOT 热天午后、CISO 傍晚光伏跌落、ISNE 冷晨和风暴过后、MISO 工业负荷偏重、SWPP 风电走廊三小时窗口。
- 交接班口头催：广东那边、SPP 两小时、罚十倍那种。
- 市场还没对上惩罚、区域还没说清、晚高峰时域还没定，先占个位子。
- 对方嫌问得细，甩“平时那套”“usual horizon”“正常惩罚”。
- 一条里又写一小时又写 45 分钟，或者 ERCO 和 CISO 绑在同一单。
- 进会前要现成 MW、高峰前要跳过审批、要关审计。
- 上一轮字段已经齐了，这一轮改口用未来负荷、跳过签字、或者反过来补上不许用测试残差。

区域只在 GD / ERCO / CISO / ISNE / MISO / SWPP 里转。时域心里按 60 / 120 / 180 写；冲突条故意写成 45、90，用来做出界。成本只认 10 / 20 / 40，缺的和用惯例顶的，备忘栏我留空。

## 写的时候有没有参考现场说法

有。短的像交接班微信，长的像丢给审批岗的备忘。中英夹杂是群里催计划时的常态。错字按打字快时会漏的字母来，区域简称打乱但同事仍能认。没有去套样本句子，也没有编还没跑出来的容量和覆盖率。

滚动窗这条，现场经常不写。说明里允许用研究室固定设置，所以 complete 里有一条点了“没写就用固定规程”，implicit_default 里又故意把固定规程和 usual 时域、usual 惩罚写在一句，避免有人把三项混成都能补。

`source_class` 一律 `independently_authored`，`author_id` 一律 `REQ-1`。单轮 `turn_id=1`，多轮四条写当前轮 `2`。`intended_*` 是我写条时心里想的字段；故意缺、故意用惯例顶、或者同一条里打架对不上的，对应栏留空。

## 哪类最好写、哪类最难写

最好写的是 missing 和 implicit_default。值班时最常见：区域回头补、惩罚还没跟市场对上、时域别按 60 猜、成本按正常走。这类不用编完整计划，按交接原话落下就行。

complete 也不难，但要克制，只写安排和可用信息，不把 MW 写进请求。

难写的是 paraphrase 和 typo。paraphrase 要把广东、CAISO、SPP、ISO-NE、十倍、四十这些口头说法对上标准字段，又不能写成 complete 那种条目清单。typo 要像真打快了：漏字母、CAIOS、ISNEE、MISSO，还得让值班同事能认。写轻了不像错字，写重了会看不懂。

conflict 要想清楚备忘栏怎么留。一小时和 45 分钟、60 和 90、20 和 40 并写时，我对不上的那一栏空着，不当场替对方选。

injection 和 multiturn 后三轮比较硬：跳过审批、当场要数、关审计、用还没发布的预报。第四条 multiturn 我改成后一轮补禁项（不许用测试残差、不许改需求曲线），字段仍按上一轮走，避免四条全是改口要违规。
